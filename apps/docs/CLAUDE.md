# CLAUDE.md — apps/docs (`@canvas/docs`)

VitePress site + TypeDoc-generated API reference.

## Commands

```bash
pnpm --filter @canvas/docs dev       # http://localhost:5173
pnpm --filter @canvas/docs build     # typedoc + vitepress build
pnpm --filter @canvas/docs preview
pnpm --filter @canvas/docs typedoc   # regenerate api/ only
```

## Editing rules

- **Document only what's exported.** Anything aspirational lives in `packages.md` or the repo-root `docs/` design notes (e.g. `docs/architecture-proposal.md`) — never inside a guide page as if it shipped. If a planned feature creeps into a code example, the example is broken.
- **Code samples must compile against the current exports.** Verify class names, option names, and import paths against `api/canvas.surface.txt` at the repo root (the pinned export list) or `packages/canvas/src/index.ts`. `@invana/canvas` has a **single** entry point — there is no `/primitives` or `/specs` subpath.
- **No `/plugins` section.** Built-in primitives are documented inside `primitives.md`; built-in behaviours inside `behaviours.md`. The renderer's five registries are extensible, not "plugins".
- **Storybook is the canonical live demo surface.** Link to it from the nav rather than duplicating runnable demos inside docs pages.

## TypeDoc

**`disableSources: true` is load-bearing — do not remove it.** By default TypeDoc resolves the
current git revision and bakes it into every "Defined in" line as
`github.com/invana/canvas/blob/<40-char sha>/…`. That made the *commit hash* part of the
generated output, so regenerating after any commit rewrote all ~1,300 committed pages with
zero API change — the diff was pure noise and buried real surface changes at exactly the
moment you most want to see them (cutting a release). With sources disabled the output is
**deterministic**: two consecutive runs are byte-identical, and `api/` changes only when the
API does. The trade-off is accepted — no click-through from a symbol to its source line.
If source links are ever wanted back, pin them (`gitRevision: "main"`) rather than restoring
the default, or stop tracking `api/` altogether (nothing in CI consumes it — `publish.yml`
builds with `--filter=!@canvas/docs`).

`typedoc.json` globs `../../packages/*/src/index.ts`, so **every** publishable package is picked up automatically — adding a package needs no config change. Output goes to `./api/` and is **committed**, so regenerate it (`pnpm --filter @canvas/docs typedoc`) in the same change as any public API move. The VitePress sidebar auto-discovers each `api/<pkg>/src/` folder via `.vitepress/config.ts` (`apiSidebar`), so new packages appear on their own.
