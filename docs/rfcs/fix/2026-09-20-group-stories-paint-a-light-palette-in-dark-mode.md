# The `graph/Groups/` stories paint a light palette in dark mode

Eight of the nine group stories mount **no** `sym:ThemeBehaviour` and **no** `sym:BackgroundLayer`,
then pin an eight-constant light palette on the node records. The pixi surface is transparent by
default, so the Storybook backdrop — which *is* themed — flips to near-black on **Dark** while every
group frame stays `0xf5f7ff` and every member label stays `0x334155`. Same shape as
`rfc:fix-2026-09-19-design-stories-ignore-the-theme-they-mount`, one contract lower: these stories
have no cards, so the `FreeformStructure` path does not apply — the repair is the **role recolour
`sym:GraphLayer` already performs**, plus deleting the pins that fight it.

| | |

| The ask | "can we make the stories in `graph/groups/` responsive to theme" |
| Non-goal | New palette roles; landing F7 / F9 of `rfc:feat-2026-09-11-a-colour-is-either-themed-or-manual-never-both`; touching `story:graph/Behaviours/GroupResize` or any `usecases/` story; changing any engine default pixel |

| ID | Hypothesis | Verdict | Evidence |

D-2 |
| R5 | The stories are broken because they never call `setData` after a theme switch | **No** | `applyTheme` writes through `sym:GraphStore.updateNode`, which re-renders; nothing is stale. Nothing publishes in the first place (S2) |
