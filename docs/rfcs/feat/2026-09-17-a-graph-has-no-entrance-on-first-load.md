## Summary

| | |
|---|---|
| **What's missing** | Nothing animates a graph's **first appearance**. After `rfc:fix-2026-09-17-auto-fit-frames-the-graph-before-the-layout-runs`, load is a hard cut: one frame empty, the next fully formed and framed |
| **Why now** | That fix deliberately removed the only motion there was — and it was the wrong motion (every node exploding out of the origin). The right motion was never built |
| **Precedent in-tree** | `sym:FadeInConnectorEffect` is exactly this, one-shot, with `durationMs` / `delayMs` / `easing` — registered as `'fade-in-connector'`. **Shapes have no counterpart**: the registry holds `shake` and `breathing` for shapes and nothing that fades in |
| **Shape of the change** | **Both routes shipped** (maintainer, 2026-09-17). Per-item sweep: C7 projects `style.effects` · C8 the behaviour · C9 its editor · C11 the React wrapper. Canvas-level: C1 `setAlpha` · C2 `config.entrance` (one flat fade over the world surfaces) · C4 `config.fitAnimation` (eased first fit). Independent and composable. **`fitOnResize` stays rejected** — see C3 |
| **Blocker found while implementing** | *(cleared by C7.)* `NodeStyle.effects` was **declared and never read** — `sym:PrimitivesRenderer.setEffect` was called from exactly one place, the badge path, and `EdgeStyle` had no `effects` field at all. A behaviour writing per-item effects would have written into a void. Row C7 |
| **What C7 buys beyond the entrance** | Every registered effect becomes reachable from data: `shake` · `breathing` on any node, `breathing-connector` · `fade-in-connector` on any edge — previously badges only |
| **Considered, rejected** | **`fitOnResize`.** It does not exist (`autoResize` only resizes the renderer + camera *viewport*), and it stays that way: re-framing on resize would override a camera the user deliberately panned. The record is C3 · D7 |
| **Open decisions** | **D9** (does `fitOnLoad` stop re-fitting once the user has panned — raised here, *not* actioned) · **D11** (the entrance plays before the config naming `activeLayout` lands — found 2026-09-18, *not* actioned) |
| **Row status** | **landed 12** · rejected 2 · superseded 1 — 15 rows, every one accounted for, so the RFC stays **landed** |
| **Regressed since landing** | **The entrance is no longer watchable on the reported surface.** Re-measured 2026-09-18: every card is already 43–100 % opaque in the *first painted frame*, because the sweep starts before the config naming `activeLayout` has landed and then burns down behind the placement gate that `rfc:fix-2026-09-17-effective-visibility-is-decided-outside-the-store` added afterwards. V12 · V19 · D11. The rows stay `landed` — each does what it says, and V18 proves the behaviour itself is exactly right — but the *feature* does not currently reach the screen, and that wants its own fix RFC |

## 2. Design

| Step | Mechanism | Rationale | Consequence |
|---|---|---|---|
| G-1 | The entrance animates **content**, not the camera | The fix just made the camera frame the final layout on its first write. A camera swoop re-introduces the class of motion that was the complaint | The frame is correct from the first painted pixel; only what is *inside* it moves |
| G-2 | The tween itself is `sym:Tween` + a named easing, driven from the engine's own frame loop | The primitive exists and is already how `sym:FadeInConnectorEffect` and `sym:animatePositions` work; no new animation machinery | Named easings only, so the config stays JSON (`sym:assertSerialisable`) |
| G-3 | *(superseded by G-4 — kept as the record)* Per-item `delayMs` is what would turn one fade into a sweep | Per-node delay makes the flow arrive in reading order rather than all at once | That is C6's job, not C2's |
| G-4 | Carried by **`CanvasConfig`**, not by a behaviour — the maintainer's call, and the better one | At canvas level the entrance is **one alpha tween on the world surfaces**, not N per-node effects: no first-appearance bookkeeping, no per-node cost, and it works for any content (graph, ER, map) rather than only for a `GraphLayer`. It is also JSON, so it rides the serialisable definition next to `fitOnLoad` | `config: { fitOnLoad: true, entrance: { kind: 'fade', durationMs: 320 } }` |
| G-5 | Fires **once per canvas**, on the first framed paint | The fit that F1 made trustworthy is exactly the moment the picture is worth showing — before it, the camera has not framed; after it, the scene is final | Re-layouts, data changes and re-fits never re-trigger it |
| G-6 | The cost of G-4: the scene fades **together**, with no sweep | A stagger needs per-item delays, which is per-item work and therefore graph-level | Kept as C6, deferred — reach for it only if the flat fade reads flat (D6) |
