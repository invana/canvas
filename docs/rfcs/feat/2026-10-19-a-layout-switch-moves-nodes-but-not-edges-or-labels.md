# A layout preset switches layout, edge shape, label placement and spacing together

**Summary:** Invana Studio's Explorer is getting **layout presets** (Network · Tree ↓ · Flow → · Radial). The user picks a card, and layout, edge shape, label placement and spacing change together, like switching a template. The canvas can't do that yet. A layout moves nodes and nothing else. ELK writes its routes into each edge's own style, so they outlive the layout that drew them. A layer's edge default is replaced wholesale by any per-edge `shape`. Nothing switches several settings as one undo step, and nothing names the switch so a playbook step can replay it.

| | |
|---|---|
| **What's missing** | One act that switches layout + edge shape + label placement + spacing, undoes as one step, keeps the selection, glides, and replays from a playbook step |
| **Root cause** | (1) `sym:ElkLayout.onPositionsApplied` writes `pathType: 'orth'` + `waypoints` into every routed edge's **own** `style.shape` with `store.internal.updateEdge`, and nothing clears them. A later force layout leaves stale elbows. (2) `sym:GraphLayer.resolveEdgeStyle` merges `shape` **wholesale**, so any per-edge `shape` (ELK's, `ParallelEdgeBehaviour`'s) hides the layer's `pathType`. (3) No preset vocabulary, no single write that covers several slices, no per-run glide |
| **Design of record (external)** | Product decisions are made and not re-opened here: `/Users/ravi.merugu/Projects/invana/invana/docs/for-developers/modules/explore/features/graph-canvas.md` GC8, GC21–GC24 and `…/explore/features/walkthrough.md` WT2–WT4 (Invana repo) |
| **Defect rows** | F2 (shallow `shape` merge) · F4 (ELK writes routes into edge data) |
| **Feature rows** | Edges: F3, F5 · Labels: F6 · Runs: F9, F10 · Presets: F1, F7, F8 · UI: F11, F12 · Bypass: F13 |
| **Decisions** | D-1–D-7 accepted as recommended, 2026-10-19. D-4 resolved as (a): every elkjs 0.9.3 `SPLINES` section is a Bézier chain (V3) |
| **Row status** | proposed 2 · accepted 3 · implemented 12 · landed 0 · deferred 0 · rejected 0 |

### The four presets (from GC22, recorded, not re-opened)

| Preset | Layout | Edges | Labels | Options |
|---|---|---|---|---|
| Network | d3 force (`pkg:@invana/graph-layout-d3-force`), `animate: false` | straight | below | Edges · Spacing |
| Tree ↓ | ELK `layered`, `direction: 'DOWN'` | orthogonal (ELK `ORTHOGONAL` routes) | below | Direction · Edges · Spacing · Root |
| Flow → | ELK `layered`, `direction: 'RIGHT'` | curved: ELK `SPLINES` routes; no route → `bump-horizontal` | right of node | Direction · Edges · Spacing · Root |
| Radial | ELK `radial` around a centre (selection, else most-connected) | curved outward (`bump-radial`) | outward | Edges · Spacing · Centre |

Colour is never part of a preset: the theme owns colour, and colour by type is the same on every layout. Options are Direction (↓ → ← ↑), Edges (Straight · Curved · Orthogonal), Spacing (Compact · Comfortable · Roomy), Root (Automatic · Selection) or Centre. A changed option is stored over the preset, with *Reset to preset*. A switch is one undo step, keeps the selection, and glides in ≤ 400 ms under 2,000 nodes (larger boards snap). ELK presets are disabled above 3,000 nodes; the host decides that limit.

### Ruled out

| ID | Hypothesis | Verdict | Evidence |
|---|---|---|---|
| R1 | Have the host rewrite every edge's `style.shape` on a switch | rejected | O(edges) data writes per switch, they land in saved data (S5), and they still lose to ELK's later writes |
| R2 | Draw ELK `SPLINES` with the existing `'smooth'` path type | rejected as-is | `'smooth'` maps to router `orth` + pathStyle `smooth` (`file:packages/graph/src/layer/GraphLayer.ts#L110-L111`). The orth router puts an L-bend between each pair of points (`file:packages/canvas-core/src/lib/geometry/connectors/routers/orth.ts`) before the spline is drawn. See D-4 |
| R3 | Make a preset a new `Layout` subclass that wraps ELK / force | rejected | A layout owns positions only (`sym:Layout.apply`). Edge shape, labels and the undo step are layer / canvas concerns, and wrapping would hide the registered instances from `layout.activate`, `useLayoutRunning` and the fitters |
| R4 | Keep the preset in Studio and call five setters | rejected | Five writes make five undo entries (or none), a playbook step can't capture them, and every other host re-builds it. GC22 / WT2 need it in the definition |
| R5 | The selection is lost on a layout run | no | No layout touches runtime states. Selection lives in `store.nodeStatesOf` and positions are written unrecorded. Checked in V5 anyway |

## 2. Design

| Step | Mechanism | Evidence | Consequence |
|---|---|---|---|
| 1 | A **preset spec** is JSON: `{ id, label, layoutId, layout: {…options}, edges: { pathType, routing? }, labels: 'bottom' \| 'right' \| 'outward', spacing: { compact, comfortable, roomy }, options: ['direction', …], maxNodes?, thumbnail }`. `layoutId` names a layout the host **registered**; the spec only patches its JSON options | `file:packages/canvas/src/engine/Canvas.ts#L1271-L1288` | Function-valued options (Studio's `collide.radius`) stay on the instance. The spec stays serialisable |
| 2 | `GraphCanvas.applyLayoutPreset(id, overrides)` expands spec + overrides into **one** `CanvasConfig` patch: `activeLayout`, `layouts[layoutId]`, `layers.graph.edge.style.shape`, `layers.graph.labelPlacement`, and `layoutPreset: { id, overrides }`. It writes the patch once with action `edit:layout-preset` | `rfc:feat-2026-09-28-canvas-definition-edits-cannot-be-undone` (an `edit:*` write is one view-history entry); `file:packages/graph/src/canvas/GraphCanvas.ts#L112-L115` | One undo step. Undo re-applies the previous slices through `_reconcileDefinition`, and `activeLayout` re-wires |
| 3 | The run started by the `activeLayout` change carries `{ transition, fitCamera: true }` (per-run, F9). It skips the glide at or above `transitionMaxNodes` | `file:packages/canvas-core/src/abstracts/Layout.ts#L104-L134`, `rfc:fix-2026-09-26-layout-rerun-glides-under-a-stale-camera` | Only a switch glides. Data-triggered runs (queries, expansions) stay as they are (GC8) |
| 4 | A layout's edge geometry is the layer's **layout geometry**: a route map (`edgeId → { pathType, waypoints }`) and a frame (`{ origin }`), written together by `GraphLayer.setLayoutGeometry(layout, …)` and owned by the layout **instance** that wrote it. Neither is store data. Every graph layout calls `layer.beginLayoutRun(this)` as a run starts; a run by any other instance clears the geometry, and so does an `activeLayout` change to an id other than the owner's | `file:packages/graph-layout-elkjs/src/ElkLayout.ts#L358-L396`. The canvas bus can't carry this: `useLayout` and the canvas-react layout wrappers call `layout.apply(layer)` directly, so their runs never reach `layout:run:start`, and ids aren't unique (the default is `'layout'`, and `useLayout` builds a fresh instance per pick) | Switching from ELK to force leaves no elbows, however the run was started. Snapshots carry no routes, because they're re-derived on the next run |
| 5 | Edge style resolves in this order: layer template → layout geometry → per-edge `style` → states, with `shape` merged **field by field**. A route is honoured only when the requested `pathType` (per-edge, else the layer's) is unset or in the route's **family**, and the families are the Edges option: *Straight* (`straight`), *Curved* (`bezier` · `quadratic` · `bump-horizontal` · `bump-vertical` · `bump-radial` · `spline`), *Orthogonal* (`orth` · `rounded` · `smooth` · `manhattan`). `step-radial`, `bundle` and the loops take no route. A requested type that draws through waypoints keeps itself; one that ignores them (`bezier`, `quadratic`, `bump-*`) yields to the route's type. Per-edge `waypoints` beat the route's. The frame's `origin` fills `pathStyleOpts.origin` of `bump-radial` / `step-radial` unless the edge sets one | `file:packages/graph/src/layer/GraphLayer.ts#L1208-L1229` | The Edges option always decides the shape: Tree + Straight is straight, Tree + Orthogonal is ELK's elbows, Flow + Curved is ELK's spline. A route never draws under a family it wasn't computed for. User data still wins |
| 6 | ELK writes routes whose `pathType` follows `edgeRouting`: `ORTHOGONAL` → `orth`, `SPLINES` → `spline` (D-4 (a)), `POLYLINE` → `straight` with waypoints. An edge ELK returns no route for has no entry, so it falls back to the layer default (`bump-horizontal` for Flow) | Run with elkjs 0.9.3: every `SPLINES` section has 3k−1 bend points, so start + bends + end is a piecewise cubic Bézier chain (V3) | Flow draws ELK's curves, Tree draws ELK's elbows, and unrouted edges still curve |
| 7 | Radial writes `frame.origin` = the centre node's position. `bump-radial` reads it as `pathStyleOpts.origin`, and `labelPlacement: 'outward'` places each label in the compass octant facing away from it | `file:packages/canvas-core/src/lib/geometry/connectors/pathStyles/bumpRadial.ts#L3-L13` | One origin serves both the edge curve and the labels |
| 7b | ELK `radial` lays out a **tree**: given a cyclic graph it stacks nodes onto a few points. `ElkLayout` hands it a spanning tree of the drawn graph, breadth-first from the centre and pointed outward, so the centre is the only node with no incoming edge. Each other component hangs off the centre by a virtual edge. Edges outside the tree are still drawn; ELK just doesn't see them. The centre is `rootNodeId`, else `resolveLayoutRoot(…, 'centre')`: the selection, else the most-connected node | Run with elkjs 0.9.3 on a 30-node cyclic graph: 26 distinct positions as given, 30 on rings (radii 0 · 111 · 193 · 207) as a spanning tree | Radial draws rings around one centre |
| 8 | `definition.layoutPreset` round-trips through `canvas.get()`, export, and a playbook step's `settings` (`canvas.update(step.settings, 'edit:playbook')`) | `file:packages/canvas/src/engine/playbook.ts#L11`, `#L108` | WT2 holds: replaying a step restores the preset and its options |
| 9 | The preset command `layout.preset` lists the specs as choice options with `disabled` + `description` when `store.nodeCount() > maxNodes` (F1). The host sets `maxNodes` in its specs | `file:packages/graph/src/canvas/graphCommands.ts#L359-L370` (`layout.activate`, the model) | The host decides the limit. The canvas only exposes the count and the disabled state |

**Example (after):**

```ts
canvas.applyLayoutPreset('flow', { direction: 'DOWN', spacing: 'roomy' });
// ≡ canvas.update({

//     layoutPreset: { id: 'flow', overrides: { direction: 'DOWN', spacing: 'roomy' } },
//   }, 'edit:layout-preset')
```
